Verziókövető rendszerek

A verziókövető rendszerek legfontosabb jellemzői

  • Változatkezelés: Minden módosítást elmentenek, így a kód korábbi állapotai bármikor visszaállíthatók.
  • Elágazások: Lehetővé teszik, hogy a fejlesztők biztonságosan, az fő kódbázistól elkülönítve dolgozzanak az új funkciókon.
  • Együttműködés: Több fejlesztő dolgozhat ugyanazon a projekten anélkül, hogy felülírnák egymás munkáját.
  • Központosított vs. Elosztott működés: A modern rendszerek elosztottak, azaz minden fejlesztő gépén megvan a teljes projekt előzménye, nem csak egy központi szerveren.
  • Nyomonkövethetőség: Pontosan látszik, hogy ki, mikor és mit változtatott a kódban.

Remote vs Local repo

Jellemző Remote Locale
Ki láthatja? Bárki, aki a repo Együttműködője Csak az, aki a gép előtt ül
Hol található? A helyi számítógépen A verziórendszerkövető-szerverén
Mi a célja? A kód írása, tesztelése és a változtatások saját mentése. Együttműködésre és biztonsági mentésre használjuk.

Legfontosabb parancsok

  • git init: Új, üres helyi Git tároló létrehozása.
  • git clone [url]: Egy létező tároló letöltése a számítógépedre.
  • git status: Megmutatja a módosított, törölt vagy még nem követett fájlok állapotát.
  • git add [fájlnév]: Kiválasztott fájl hozzáadása a követett változtatásokhoz. A git add . az összes fájlt hozzáadja.
  • git commit -m "üzenet": A véglegesítés. Elmenti a hozzáadott változtatásokat egy egyedi üzenettel a helyi történetbe.
  • git push -u origin [ág-neve]: A helyi commitok feltöltése a GitHubra.
  • git pull: Letölti és azonnal be is olvassza a távoli szerveren lévő legfrissebb módosításokat a helyi kódodba.
